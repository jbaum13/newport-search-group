# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marketing website for Newport Search Group ("Human Relationships. Agentic Execution.") — a zero-dependency static-site generator. There is no `npm install`; plain Node >= 18 only. One content source (`src/content.js`) drives both the live website (`dist/`) and a paste-ready Wix document (`WIX-CONTENT.md`), so the two never drift.

## Commands

```bash
node build.js            # generate dist/ (19 pages + sitemap + robots)
node build.js --wix      # also regenerate WIX-CONTENT.md  (= npm run build)
npm run preview          # build --wix, then serve dist/ at http://localhost:8766
npm run clean            # rm -rf dist
BASE_PATH=/newport-search-group npm run build:site   # sub-path build (GitHub Pages project site)
```

```bash
npm test                 # build, then run the agent smoke test (skips if Playwright is absent)
FINN_ENDPOINT=https://… BEACON_ENDPOINT=https://… node build.js   # point the agents at real services
```

`.github/workflows/deploy.yml` builds and publishes `dist/` to GitHub Pages on every push to `main`, auto-detecting the Pages base path. `.github/workflows/test.yml` runs the smoke test on every pull request and fails if `WIX-CONTENT.md` has drifted from `src/content.js` — regenerate it with `node build.js --wix` and commit the result.

## How build.js produces dist/

`build.js` requires `src/content.js` (site meta, nav, footer, pages, CTA blocks, SEO keywords) and `src/articles.js`, then renders each page's array of typed sections (`hero`, `cards`, `split`, `list`, `stats`, `cta`, `form`, …) to HTML with shared header/footer chrome. Routes map to pretty URLs: `/a/b` → `dist/a/b/index.html`. It also:

- copies `src/styles.css` / `src/main.js` / `src/assets/` into `dist/`, cache-busting CSS/JS URLs with a short content hash;
- prefixes all internal links with `BASE_PATH` when set (absolute/`mailto:`/`tel:` URLs are left alone);
- renders `src/articles.js` entries under `/resources/<slug>`, sorted by date;
- renders the right agent's launcher into every page and injects `window.NEWPORT_AGENT_CONFIG` (see **Agents** below);
- carries inline SVG line-icons keyed by a card's `icon:` field (unknown keys render nothing), and degrades image sections to placeholders when the asset file is missing from `src/assets/`;
- with `--wix`, additionally writes `WIX-CONTENT.md` (theme, fonts, menu, per-page SEO, and every section's copy for pasting into the Wix Editor).

## Agents (Finn & Beacon)

Two conversational agents share one runtime. **`AGENTS.md` is the reference** — read it before changing their answers, routing order, or the adapter.

- `src/agent-core.js` is the agent-agnostic runtime; `src/finn.js` and `src/beacon.js` are profiles (identity, quick actions, guardrails, knowledge layer); `src/agent.css` styles them all, with per-agent accents on `[data-agent]`.
- **One agent per page.** `agentForRoute()` in `build.js` sends candidates to Finn (`/jobs`, `/contact`, `/resources/*`) and everyone else to Beacon. Two floating launchers on one page would be noise; the smoke test asserts exactly one.

Three rules that are easy to get wrong:

- **No agent holds a credential.** This site is static; `FINN_ENDPOINT` / `BEACON_ENDPOINT` are build-time URLs to services you run, and those hold the keys.
- **Answers from a remote endpoint render as text, never HTML.** Only the built-in knowledge layers emit markup.
- **Beacon never states a number.** No market statistic, comp benchmark, or named company's hiring activity — he has no verified dataset connected, and the smoke test fails the build if a figure appears in his transcript. Keep new answers number-free until a real source is wired in.

The `agentCta` section type drops a contextual block into any page (`agent:` picks who, `seed:` pre-sends their first question).

## Editing rules

- **All copy lives in `src/content.js`** — edit data there, never hand-edit `dist/` (generated) or `WIX-CONTENT.md` (generated by `--wix`).
- Agent answers live in the `kb` arrays in `src/finn.js` and `src/beacon.js` — treat them as content, and keep them consistent with `src/content.js`.
- `src/styles.css` is the design system (navy / steel / electric-blue, Inter, responsive); `src/main.js` is light client JS (mobile nav, contact-form intent prefill).
- Character art in `src/assets/`: `duke.png`, `scout.png`, `finn.png`, `beacon.png` — all transparent cutouts, so each composites onto the card gradient rather than sitting on a baked-in box. Keep new character art transparent. `finn-avatar.png` / `beacon-avatar.png` are the 128px head crops for the launchers, panels and CTAs. (`duke.jpg` / `scout.jpg` are the superseded originals; nothing references them.)
- Logo assets in `src/assets/`: `logo.png` (color, light backgrounds), `logo-white.png` (+`@2x`, dark header/footer), `favicon.png`.
- `_archive-velo-execsearch/` (if present) is an unrelated archived Velo/Wix build — reference only.

## Routes

`/agentic-platform/duke-and-scout` was renamed to `/agentic-platform/meet-the-agents` when Finn and Beacon joined. `build.js` emits a canonical-tagged meta-refresh stub at the old path — GitHub Pages has no server-side redirects, so don't delete it.

## Known gaps (from REVIEW.md)

The contact form and Jobs search are not wired to anything yet — before a real launch, connect the form (`build.js` `form()` / `src/main.js`) to a CRM/email and Jobs to an ATS. REVIEW.md lists remaining recommendations: proof/case studies, lead routing, a real job feed, Resources content.
